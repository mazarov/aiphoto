# Правка стикера текстом

Ветка: `feature/06-10-sticker-from-result` (поверх незакоммиченного «Сделать стикер»; отдельная ветка от `main` потеряла бы этот rail).

## Контекст

На результате фото «Что изменить» открывает remix промпта и image-job без `edit_kind=sticker`. На результате стикера та же кнопка должна менять сам PNG.

Эмоция и движение уже так работают: родитель — завершённый стикер, вход модели — его PNG, финал — `finalizeStickerImage`. Свободный текст — то же действие с другим промптом, не remix и не кнопка «Текст» (та бесплатно рисует буквы).

## Контракт

`stickerAction=revise`. Пресет не читается. Хинт 2–120 символов (`sanitizeStickerCustomHint`).

```
POST /api/generate
{ editKind: "sticker", parentGenerationId, stickerAction: "revise", stickerCustomHint }
```

- Родитель: `edit_kind=sticker`, completed, свой. Иначе 400 «Изменить можно только готовый стикер».
- `photoStoragePaths` пустые. Иначе 400 «Правка делается у готового стикера».
- Пустой хинт: 400 «Опишите, что изменить».
- `prompt_text`: `STICKER edit=revise preset=custom\n<hint>`.
- `edit_instruction`: тот же хинт. RPC SQL 273 уже требует непустую инструкцию, когда родитель — стикер. Новой миграции нет.
- Цена и модель — `sticker_model`, как у эмоции.
- Fingerprint: `stickerEditFingerprintFields` (action отличает revise от emotion с тем же текстом).

Воркер узнаёт правку **только** по маркеру в `prompt_text` (`parseStickerEditFromPrompt`). `edit_instruction` в промпт не подмешивается. `assembleStickerEditFinalPrompt` для `revise`: изменить только запрошенное; человек, стиль, кадрирование и фон остаются; одежда и поза меняются, только если об этом попросили. Фон magenta или transparent — как у остальных стикер-джобов. Лог `generation_prompt_resolved.stickerEdit`.

## UI

Один стикер: primary rail «Что изменить» открывает `StickerActionSheet` без чипов пресетов. «Выйти» над «Изменить стикер · N✦». Пока джоба идёт, шит остаётся и показывает прогресс.

Стикерпак: кнопки нет (у тайла нет своей строки). Фото-результат по-прежнему идёт в remix.

Цепочка: новый результат снова `edit_kind=sticker`, следующее «Что изменить» правит его.

«Сменить стиль» берёт PNG этого стикера как фото (`parentGenerationId` = стикер на экране, `edit_instruction` пустой, промпт нового стиля). Исходный кадр не подмешивается. SQL `274`.

## Ограничения

Текст и обводка впечатаны в PNG. `revise` такого родителя отдаёт модели уже с плашкой. Эмоция ведёт себя так же. В v1 не блокируем.

Крупная смена стиля («сделай аниме») на вырезанном стикере хуже, чем «Сменить стиль» с фото. Подсказка поля это говорит, слова не запрещает.

Второе референс-фото (исходный кадр) в v1 не передаём.

## Выкат

Флага нет. Лендинг и воркер — один релиз: старый воркер не узнает `edit=revise` и соберёт первичный стикер из хинта. Откат — revert коммита.
