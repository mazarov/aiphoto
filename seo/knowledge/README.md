# База знаний по продвижению

Источник фактов для роли [senior-seo-strategist-ru](../../.cursor/rules/senior-seo-strategist-ru.mdc). Роль читает нужный файл по рынку перед рекомендацией и не подменяет пустые разделы общими знаниями.

## Приватность

Содержимое базы — конспекты закрытых курсов и внутренние выводы. **В git попадает только этот README.** `yandex.md`, `google.md` и всё остальное в папке исключены через `.gitignore` (`seo/knowledge/*`, `!seo/knowledge/README.md`). Репозиторий публичный — не снимать исключение и не копировать записи базы в правила, доки или коммиты. Резервная копия — вне репозитория (личное хранилище), не ветка.

## Правила ведения

1. **Одна запись — один проверенный вывод.** Формат записи:

   ```
   ### <Короткий тезис>
   - Что: <факт / правило поведения поисковика>
   - Откуда: <официальный источник / эксперимент на promptshot.ru / ответ поддержки / наблюдение по Вебмастеру-GSC + дата>
   - Что это значит для нас: <конкретное действие или ограничение для каталога / генератора>
   - Проверено: YYYY-MM-DD
   ```

2. **Пустой раздел помечается `_пусто_`.** Роль обязана сказать об этом пользователю, а не заполнять из головы.
3. **Не смешивать факт и гипотезу.** Гипотезы — в раздел «Гипотезы к проверке» с датой и способом проверки.
4. **Дата в шапке файла** обновляется при каждой правке.
5. **Источник обязателен.** Запись без «Откуда» не добавлять.
6. Данные по конкретным страницам (позиции, спрос) сюда не пишутся — они в `webmaster-page-collect/inbox/` и `seo/<slug>/`.
7. Сокращения источников в шапке `google.md` / `yandex.md`: **Шакин v.38**, **Мур ~2020**. Новый конспект — новая аббревиатура + дата разбора, не смешивать с уже записанным.

## Как пополнять

Пользователь присылает материалы (выгрузки, статьи, ответы поддержки, результаты экспериментов). Агент раскладывает по разделам нужного файла в формате выше и показывает diff до коммита.
