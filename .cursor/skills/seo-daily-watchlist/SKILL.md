# SEO daily watchlist

Роль: [senior-seo-strategist-ru](../../rules/senior-seo-strategist-ru.mdc), режим **дневной сводки**, не 8 блоков архитектуры сайта.

Цель: **одно** самое важное за вчера по топ-30 URL и одно действие. Не таблица из 30 строк.

## Когда вызывать

- «самое важное за вчера», «сводка SEO», «что случилось в поиске»
- `@seo-daily-watchlist` / `@senior-seo-strategist-ru` + вчера / вотчлист

Один отчёт на календарный день. Если `reports/seo/YYYY-MM-DD-daily.md` уже есть за сегодня — покажи его и спроси, надо ли пересчитать. Не гоняй скрипт повторно без явной просьбы.

## Данные

Не читай целиком `landing/src/data/seo-watchlist-snapshot.json` (~2 МБ).

1. Запусти из корня репо:

```bash
node .cursor/skills/seo-daily-watchlist/scripts/yesterday.mjs
```

2. «Вчера» = `webmasterDay` (последний день в снимке), база = день до него. Вебмастер обычно отстаёт на 1–2 дня — всегда назови обе даты и `lagDays`.
3. Если снимка нет или `lagDays > 3` — скажи, что цифры старые. Обновление только по просьбе: `node src/standalone/refresh-seo-watchlist.mjs` (OAuth в `.cursor/yandex-seo.env`). Не пиши секреты.
4. MCP `search_queries` не использовать как основу: там нет привязки запрос→URL. `search_urls` — запасной live-срез, не замена снимку.

Список URL: `landing/src/data/seo-watchlist-paths.json`. Экран: `/admin/seo`. Спека: `docs/21-08-seo-page-watchlist.md`.

## Как выбирать «самое важное»

Скрипт уже ранжирует `top[]` по `score` (потеря/прирост кликов, просадка позиции, падение CTR на топе).

Возьми `top[0]`, если это не шум. Переопредели, только если ниже по списку есть более дорогой **page-owner** сигнал:

| Сигнал | Когда главнее сырого Δ кликов |
|---|---|
| Корень `/` забрал ВЧ («промты», «промт для фото») у кластерной страницы | каннибализация важнее локального +кликов |
| Позиция +0.5 и больше при ≥80 показах | страница теряет полку |
| CTR −2 п.п. и ниже на позиции ≤10 | сниппет/интент, не «мало трафика» |
| Кластерная страница просела, а запросы ушли на соседний URL | одна страница-владелец |

Запрещено:

- пересказывать все 30 URL;
- чинить сниппет, если проблема — интент или каннибализация;
- объявлять деиндексацию без данных;
- выдумывать запросы, которых нет в `top[].queries`.

Пороги шума: страница с |Δ кликов| < 5 и без `position_worse` / `ctr_drop` — не лид.

Если сумма Δ кликов у `queries` не объясняет страницу — так и скажи: в снимке только топ-20 запросов Вебмастера, виновник может быть ниже. Не подгоняй мелкие запросы под большой URL-сдвиг.

## Ответ пользователю

Сначала лид. Потом коротко цифры. Потом одно действие.

```markdown
# Самое важное за [webmasterDay]

**[одна фраза: страница + что случилось + почему это бьёт кластер].**

Вчера Вебмастера: [webmasterDay] (лаг [lagDays] дн. к [calendarToday]). База: [baselineDay].

- Страница: [path](https://promptshot.ru[path])
- Показы / клики / CTR / позиция: … → … (Δ …)
- Запросы-виновники: «…» (Δ клики, позиция)

## Одно действие сегодня

[Одно. Владелец URL, не список правок по сайту.]

## Ещё смотреть

- до 4 строк из `top[1:]` — только если score не шум
```

Не используй формат «SEO strategy / architecture / clusters» из правила стратега.

Сохрани тот же текст в `reports/seo/[calendarToday]-daily.md`. Если каталога нет — создай. Не коммить, пока не попросили.

## Проверка перед ответом

- Лид один, и он про страницу, не про «сайт в целом», если есть явный URL-виновник.
- Есть вчера / база / лаг.
- Действие одно и проверяемо завтра тем же скилом.
- Полный snapshot не открывался.
